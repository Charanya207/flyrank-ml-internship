Google Search Ranking & Discoverability Capstone

Content Refresh & Opportunity Scoring — FlyRank ML Internship

Abstract

This capstone asks which anonymized content should be prioritized for refresh and review using visibility, engagement, freshness, and decline-risk signals. The workflow combines an interpretable CTR-and-freshness baseline with machine-learning models evaluated using a client-holdout split. On the measured validation set, Logistic Regression achieved an F1-score of 0.7258, Decision Tree 0.8314, and Random Forest 0.8239. The Decision Tree had the highest measured F1-score among the three tested models, while the workflow also produced ranked content-prioritization output for human review. These results are directional decision support and do not establish that refreshing content causes higher rankings, clicks, or traffic.

1. Introduction / Problem Statement

Content teams may have many pages that could be reviewed but limited time to inspect them manually. This project creates a repeatable analysis to prioritize anonymized content for refresh or further investigation using measurable signals.

The decision supported is which content should be reviewed first. The output is a prioritization aid, not an automatic publishing or deletion system.

2. Data

The analysis uses the anonymized FlyRank internship content-refresh dataset. It contains 30,000 records and 44 columns, including visibility, clicks, sessions, CTR, engagement, content age, freshness, position, content type, and search-intent features.

Content identifiers, client identifiers, trend direction, trend percentage, and the target label were excluded from the model feature set. No client names, domains, private queries, credentials, or raw private data are exposed.

3. Methodology

Baseline

The baseline uses CTR and content freshness as practical ranking signals. Higher CTR and fresher content receive a higher refresh-priority score.

Models

The target variable is is_declining_label. Logistic Regression, Decision Tree, and Random Forest were compared.

Validation

A client-based holdout design was used: 25 training clients and 7 test clients, with zero client overlap. Training contained 26,581 rows and testing contained 3,419 rows.

Leakage audit

Content ID, client ID, trend direction, trend percentage, and the target label were excluded from model features, and a separate audit checked that these fields were not present in the feature set.

5. Limitations & Honest Framing

  • Results depend on the available anonymized dataset and validation design.
  • Performance may change for new data, clients, or search conditions.
  • The analysis identifies associations and supports prioritization; it does not prove causal effects.
  • The project does not prove that refreshing content will increase Google rankings, clicks, or traffic.
  • Human review is required before publishing, deletion, or major strategy decisions.

6. Ranked Recommendations

The final workflow produces a ranked content-review queue using refresh-priority signals and model-based decline-risk information. Higher-ranked items should be reviewed first.

PriorityReview focusSuggested action
1Strong review opportunityReview freshness, CTR, engagement and current relevance.
2Decline-risk signalInspect recent performance and determine whether a refresh is justified.
3Low CTR / visible-page opportunityReview title, metadata and content alignment.
4Low engagementInspect content usefulness and engagement signals.
5Stale contentCheck whether information is outdated and whether an update is appropriate.

These recommendations are human-review decision support and should not be fully automated.

7. Reproducibility

The workflow was developed in Python using pandas, scikit-learn, and Matplotlib in Google Colab. The repository contains the internship notebooks and capstone notebook under work/notebooks/.

Workflow: data loading → feature exclusions → baseline → model comparison → client-holdout validation → leakage audit → ranked recommendations.
